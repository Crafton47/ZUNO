# Security Policy

## Supported Versions

ZUNO is under active development. Security updates are applied to the latest code on the default branch.

| Version | Supported          |
| ------- | ------------------ |
| 2.x     | :white_check_mark: |
| < 2.0   | :x:                |

## Reporting a Vulnerability

We take the security and privacy of ZUNO users seriously. If you discover a security vulnerability or credential leak, please report it privately rather than opening a public issue.

### Private Reporting Channels

1. **GitHub Private Vulnerability Reporting**: Use the **"Report a vulnerability"** tab under the Security tab of the official GitHub repository once published. This provides an encrypted, private channel directly to the maintainers.
2. If private vulnerability reporting is unavailable, reach out directly to the repository maintainer through private platform messaging before public disclosure.

### What to Include

Please provide:
- A description of the vulnerability and its potential impact.
- Step-by-step instructions or a minimal reproducible proof-of-concept (PoC).
- Affected endpoints, parameters, or components.
- Any suggested remediation or workaround.

### Disclosure Policy

- Maintainers will acknowledge receipt within 48 hours.
- We will work with you to understand and validate the report and develop a fix.
- We request that you give maintainers reasonable time to remediate the vulnerability before public disclosure.
- Security advisories will credit reporters who practice responsible disclosure.
